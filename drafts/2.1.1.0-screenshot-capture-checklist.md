# Armorsmith documentation screenshot capture checklist

Companion to **Armorsmith-documentation-audit.md**. Review baseline: Perforce CL1037, October 30, 2026. Target for new interface/foam captures: **2.1.1.0**, the next update identified by Randy. No matching release-candidate build was verified during the audit. These are capture instructions, not claims that captures or the workflows have passed.

**No screenshot work for Printable Figure:** Randy confirmed it is disabled because it does not work. Remove its documentation claims. Printable Details, model-derived Create Patterns, and foam build sheets also have withheld entry points or release guards; they are excluded from the capture session.

## Shared capture setup

- Use actual application captures from the documented build. Record version, build ID/CL, feature selection, OS display scaling, app UI scale, viewport size and date in the capture notes. Do not mix 2.1.0.10 screenshots with 2.1.1.0 Workbench instructions.
- Use English, the existing dark theme, one monitor/display scale and a consistent application size. Prefer a 1920 × 1080 or larger native window where text is readable; crop instead of shrinking the full screen into a narrow article. Preserve the chosen grid/background across related images. Avoid temporary windows, video overlays, personal filenames and debug panels.
- Save untouched originals and annotated derivatives separately. Export PNG at native capture resolution. Keep new repository assets under `images/`; filenames below are proposed. Callouts should supplement visible UI labels, not replace them.
- Capture after sliders settle and geometry returns to final detail. Do not use the deliberately simplified interactive foam preview as the finished result. Keep a saved checkpoint before every destructive edit or reset.
- “Required” means the planned illustrated instructions depend on this view. Optional images may be omitted when precise text already explains the step. They should not delay correcting wrong instructions.

### Reusable example projects

**A — Fitted armor:** Create a documentation copy named `Docs fitting.costume` with a measured adult built-in avatar, one simple helmet and paired bracers in distinct workspaces. Attach helmet to head and bracers to appropriate forearm slots. Add one unused workspace to demonstrate browsing without clutter. Use assets owned or licensed for documentation; the local `Art/Test/HELMET.stl` is a candidate, not a verified final example. Use a rigged body for animation. Save neutral pose and an arms-bent checkpoint. No existing personal costume should be overwritten.

**B — Foam bracer:** Create `Docs layered bracer.costume` with one drafting workspace. Base outline: rectangle **180 × 100 mm**, **6 mm** thick, **Horizontal Bend 90°**. Add two closed **40 × 25 mm** outlines, each **2 mm** thick, within the base. Put them into the first foam layer at **Height Above Base 0 mm**. For a second-layer example, add a **25 × 15 mm** badge at **Height Above Base 2 mm**. Use a neutral gray base and contrasting preview colors on raised pieces. Use the candidate's normal default triangle budget first and record it rather than assuming a new default. Save flat, formed, layered, and attached checkpoints. Arrange the flat cutting shapes apart on paper; their assembly positions should still visibly fit the base.

**C — Avatar practice:** Create a separate adult built-in female avatar documentation copy. Use explicit practice values, for example standing height **175 cm**, underbust **80 cm**, full bust **95 cm**, only if accepted by the target build. These are demonstrations, not recommended body proportions. Verify displayed values and locks after each edit. Retain an unmodified checkpoint before the guide's body selector or reset controls are used.
